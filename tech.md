#  Инфоброкер PatinAi (мультилингвальный)
#  ([Subito.it](http://Subito.it) ↔ Восточная/Западная Европа)
##  1\. Концепция и User Flow
Система функционирует как асинхронный коммуникационный прокси-сервер, устраняющий языковой барьер между итальянскими продавцами-наследниками и покупателями из ЕС.
###  Сценарий А: Покупатель (Польша, Литва, Германия, Франция)
  -   **Язык интерфейса:** Динамический (определяется `language_code` Telegram или первым запросом).
  -   **Ввод запроса (L1→L2L\_1 → L\_2L1​→L2​):** Пользователь пишет на родном языке (напр., польский). Локальная модель NMT (`Helsinki-NLP/opus-mt-pl-it`) переводит текст в итальянский вектор поиска.
  -   **Поиск:** Бот скрапит [Subito.it](http://Subito.it) по итальянскому запросу.
  -   **Отображение (L2→L1L\_2 → L\_1L2​→L1​):** Итальянские заголовки и описания лотов транслируются обратно на язык покупателя для ознакомления.
  -   **Коммуникация:**
  -   Покупатель задает вопрос о товаре на своем языке.
  -   Бот переводит его на итальянский и отправляет продавцу.
  -   Ответ продавца (IT) переводится покупателю (L1L\_1L1​). Контекст диалога сохраняется statefully.
###  Сценарий Б: Продавец (Италия)
  -   **Интерфейс:** Строго моноязычный (итальянский).
  -   **Onboarding:** Регистрация лота через фото + описание.
  -   **OCR Pipeline:** Извлечение текста с фотографий (таблички мастеров, дефекты) локальным PaddleOCR. Текст добавляется к метаданным лота для улучшения индексации.
  -   **Управление:** Получение уведомлений «У вас новый вопрос», где текст вопроса уже переведен на понятный итальянский.
##  2\. Технический стек (Локальное исполнение, CPU-only)
| Компонент | Технология | Назначение |
| --- | --- | --- |
| Framework бота | Python, aiogram v3.x | FSM (Finite State Machine), управление сложными диалогами, инлайн-кнопки. |
| Сбор данных | httpx, BeautifulSoup4 | Парсинг выдачи Subito.it (HTML/JSON API). |
| Машинный перевод (NMT) | transformers + модели Helsinki-NLP (opus-mt-xx-it) | Офлайн-перевод запросов и ответов (PL↔IT, DE↔IT, FR↔IT, EN↔IT). Вес пары ~300 МБ. |
| Семантический поиск | sentence-transformers (paraphrase-multilingual-MiniLM-L12-v2) | Векторизация текстов до этапа перевода для функции рекомендаций («горячо-холодно»). |
| Компьютерное зрение | PaddleOCR (CPU build) | Распознавание текста на фотографиях мебели (критично для итальянского рынка со слабыми описаниями). |
| Хранилище | SQLite + FAISS | Persistence истории сессий, избранного и индекс векторов объявлений. |
##  3\. План реализации (Sprint Plan V3)
  1.    **Инфраструктура MT (Days 1-2):** Интеграция офлайн-моделей MarianMT. Создание middleware детектора языка. Тест двунаправленного перевода без потери спецсимволов.
  2.    **Stateful Dialogue & OCR (Days 3-4):** Реализация графа состояний покупателя (FSM). Разделение баз данных покупателей и продавцов. Подключение PaddleOCR к пайплайну загрузки фото от итальянцев.
  3.    **Кэширование семантики (Day 5):** Оптимизация latency. Переводятся только уникальные фразы; результаты кэшируются в SQLite. Векторизация описаний происходит один раз при первом появлении лота.
  4.    **UI/UX и нотификации (Day 6):** Динамическая локализация кнопок управления. Настройка системы прямых сообщений (Direct Messages) для оповещения покупателя об ответе продавца вне зависимости от активной сессии поиска.
##  4\. Критические риски и архитектурные решения
| Риск | Решение / Митигация |
| --- | --- |
| Задержка (Latency) | Инференс двух моделей MT + OCR + Search на одном CPU занимает >10>10>10s Решение: Использование очереди задач (Celery/RQ в минимальном сетапе) для фонового выполнения. Пользователю мгновенно возвращается заглушка «Перевожу…». |
| Семантический дрейф | Искажение терминов антиквариата (intaglio, pavimentazione, patina) машинным переводом. Решение: Пост-редактирование через пользовательский глоссарий (Glossary Layer) — словарь фиксированных соответствий терминов поверх вывода нейросети. |
| Асинхронность связи | Продавец отвечает спустя неделю, когда окно чата покупателя закрыто. Решение: Bot инициирует новое личное сообщение пользователю с текстом ответа, не пытаясь продолжить старую ветку диалога. |
| Бан парсера | Эмуляция поведения человека (интервал 3–7 сек между запросами), использование только мобильной версии сайта, отсутствие параллельных потоков скачивания. |
##  5\. Результат работы (Deliverables)
Проект представляет собой исполняемый пакет скриптов:

1. *broker_core.py*: Ядро FSM и маршрутизации сообщений.

2. *translator_engine.py*: Класс-обертка над моделями Helsinki-NLP с поддержкой глоссария.

3. *vision_service.py*: Микросервис обработки изображений через PaddleOCR.

4. *requirements.txt*: Список зависимостей (включает ссылки на загрузку .pt файлов MarianMT для оффлайн-режима).

5. Демонстрационный лог сквозного цикла: \[Пользователь PL\] → \[Bot IT\] → \[Продавец IT\] → \[Ответ\].
